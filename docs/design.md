# ZZP 设计与仓库规范

版本 1.0。ZZP 是展示身份，zzpice 是 GitHub 账号；`zzp.moe` 是公开项目的总入口。名称先表达用途，仓库代号用于源码、路径和技术说明。既有仓库名、raw 地址、应用 ID、存储键与部署来源保持稳定，避免为改名制造迁移成本。

## 视觉语言

暖白底、深绿文字、低饱和绿强调。使用系统字体、常规字重、细边框和少量圆角；不引入外部字体、装饰渐变或默认卡片阴影。内容与图片本身承担视觉重点。

| 角色 | 浅色 | 深色 |
| --- | --- | --- |
| 页面底色 | `#f5f5ef` | `#151c19` |
| 内容表面 | `#fffefa` | `#1e2822` |
| 辅助表面 | `#eaf0e4` | `#2d3e2d` |
| 正文 | `#223b30` | `#e0e8df` |
| 次要文字 | `#5c6c62` | `#a3b4a7` |
| 边框 | `#dce1d6` | `#344238` |
| 强调与焦点 | `#316348` | `#a9ceaa` |
| 强调底上的文字 | `#fffefa` | `#15251b` |

色值和字体以根目录 [design.css](../design.css) 为准。`--zzp-*` 是跨项目原语，各项目原有语义变量映射到它们；不要再叠加一套覆盖主题。提示、错误、图表系列和媒体预览可保留专用颜色，但不能只靠颜色传达含义。

正文通常 16px，说明 13–14px，标题按信息层级使用 20–32px；高密度工作区可适当减小，手机输入框至少 16px。间距以 4px 为基数，常用 8 / 12 / 16 / 24 / 32。控件圆角 8px、卡片 12px、较大容器 16px。主要操作和独立导航至少 44px 高；文本中的链接保留自然行高。

浅深色共用结构，默认跟随系统。已有显式主题选择保留，主题偏好留在本应用；不新增跨站同步。焦点使用 3px 强调色轮廓；支持跳转到主内容、键盘和减少动态效果。不能用悬停作为唯一操作入口。

## 身份与导航

公开网页使用「用途 · ZZP」标题。应用图标共用深绿底、浅色线条、相同安全区与圆角，通过用途图形区分；社交图使用同样的颜色和文字层级，不使用用户数据或截图中的私人内容。

应用顶部保留轻量的「ZZP / 工具与资源」链接，页脚提供「所有项目」和当前仓库。主站是唯一项目目录，不把项目清单复制到每个应用。内部导航在当前页面打开；返回主站等跨项目入口用新标签页和明确的辅助标签，保护当前工作上下文；外链使用 `noopener noreferrer`。

项目首页、具体工具、资料页分别承担入口、操作、说明。不同项目无需同样的页头高度、栏数或页面宽度：入口侧重浏览，资源站侧重图片，编辑器侧重工作区，计算工具侧重输入与结果。网页默认宽度约 1080–1120px，复杂工作区可达 1440px。窄屏自然堆叠，不压缩桌面侧栏或依赖横向整页滚动。

## README 与仓库

README 开头依次为：用途标题、一句话说明、主要使用入口、必要的起步步骤。公开展示项目链接到总入口；只有真实的检查或更新状态使用一个原生 Actions badge，许可用普通链接。避免大幅横幅、重复形容词、装饰 badge 和重复的项目目录。

后续内容按项目选择：使用、源码或文件职责、维护与验证、边界、来源与许可。小仓库在 README 内说明即可；复杂项目链接到 `docs/` 或已有专属维护文档。AGENTS.md 只写协作限制和指向维护文档的链接，不复制完整教程。

路径与新文件名优先小写英文和短横线；`README.md`、`LICENSE`、`AGENTS.md` 及工具约定文件保留标准名称。人工源码和生成产物要明确区分，生成文件标明更新命令，历史版本交给 Git，不增加重复备份目录。不要为了形式一致移动已有稳定的资源路径、卡片标识或配置源。

## 公开与私有

主站只手动收录确认适合公开的项目，项目列表仍只在 `index.html` 维护。禁止从账号仓库清单自动生成导航；公开 HTML、README、注释、图标、OG 和 manifest 均不能引用私有仓库的名称或元数据。

私有配置只在私有范围内维护；不为统一增加网页或公共入口。公网配置只保留可分享设置，设备映射、服务器信息、认证和私人路径独立保管。自动校验日志输出检查结果，不输出敏感值。隐藏入口、折叠区域、前端密码和 robots.txt 不提供访问控制。

## 复用与更新

各网页仓库在本地保存同一份 `design.css`，不从主站 CDN 动态加载。修改共同语言时先修改本规范及原文件，再在同一轮复制到相关项目并验证；各项目不增加包、子模块、构建器或自动同步机器人。

图标与社交图也就地保存。只在设计实际变化时替换，不建立另一份运行时项目清单。离线应用同步更新自己的缓存版本和完整资源清单，不能让新页面混用旧样式；主站仍不注册 Service Worker。

验证按影响执行：网页检查 320 / 390 / 768 / 1440px、浅深色、缩放、键盘、导航、主要操作与无网络行为；README 检查链接和层级；规则与配置沿用现有校验，不无故重建生成文件。发布后核对 Pages、HTTPS 和资源版本。每次跨仓库提交前确认远端未被其他维护任务更新，并单独复核公开 diff 的隐私边界。
